## v1.7.2 — 2026-08-30

- delegate done-state flow: a finished codex delegate no longer drops to a lingering shell tab — delegate ptys skip the shell fallback entirely, the terminal-bar tab closes itself on exit (selection hands back to the parent session), and the delegate's card swaps "change pokemon" for a pokéball despawn button. Clicking it plays the SAME pixel pokéball recall the done subagent battlers get (`spawnPokeballRecall` reused verbatim via a new `Walker.startRecall` — delegates are session walkers, not battlers), and the session is only torn down from the animation's completion callback. A codex that finishes before the renderer even adopts it still lands in 'done' via a main-side retained exit record
- fixed phantom subagent battlers spawning from codex output: the pty parser's battle heuristics (spawn/attack/endAll) regex-matched codex's verbose stream as Claude-style Task/tool lines, materializing up to five fake pokemon per delegate session. Battle signals are now claude-only (real ones come from hooks); status/tool derivation for non-claude sessions is unchanged. Delegated to codex gpt-5.6-luna, verified and merged by the orchestrator (as are all luna bullets below)
- fixed the black screen when rapidly clicking between garden and terminal views: each garden ↔ fullscreen toggle destroyed and recreated the selected terminal's xterm WebGL context, and the churn eventually made Chromium evict the garden's own Pixi context. The selected session's terminal context is now retained across toggles (at most one terminal WebGL context alive, released only when another session attaches or the terminal is disposed), and the context-loss auto-rebuild alarm dropped from 10s to 2s
- generalized the IME/dictation scroll guard: Chromium scrolls every scrollable-box ancestor (overflow:hidden included) to reveal the composition caret, so intermediate layout containers could still be shifted unreachably — the arceus card clipped off the roster strip's left edge with no way to scroll back. The capture-phase guard now clamps any scrolled element back to 0 unless it (or an ancestor) is an intentional scroller: an audited allowlist, anything inside .xterm, and form fields
- delegate session UX: codex delegates spawn with `-c hide_agent_reasoning=true` so their terminal shows tool activity and results instead of the full reasoning stream; compact roster cards carry a tiny mono provider tag (claude/codex) plus the delegate's "↳ parent" line; a spawning delegate no longer steals the terminal-split selection (adopts in the background); and a delegate terminal opened mid-run scrolls to the bottom of its backlog and follows live output
- the model badge's "↺ changed from" tick no longer shows `<synthetic>`: Claude Code transcripts stamp internal placeholder entries with angle-bracketed model ids, which costWatcher surfaced as a real model change. The last real model is now held through placeholder blips, stored placeholder ticks are scrubbed, and the tick only ever reports genuine switches
- new-agent dialog: the working directory defaults to the active workspace's folder, then most-recent, then `~`; the provider preselects a new "default agent provider" setting (settings → segmented control, default claude); with many pokemon the dialog body scrolls behind a pinned footer so create/cancel never leave the screen; and a "just a terminal" action starts the user's shell at the chosen directory as a real `shell`-provider session — no hook wiring, no output parser, so shell output can never fake battle or status signals
- cleaned up the fullscreen view's topbar chips row: the session/garden chip scrollers hide their chunky scrollbars behind right-edge fades (wheel scrolling still works, same affordance as the roster strip), the workspace switcher keeps a stable clamped width instead of being squeezed mid-word, and chips cap their width with ellipsized titles

## v1.7.1 — 2026-08-30

- first-class delegate sessions: the orchestrator can now ask the running app to spawn a `codex exec` task as a REAL pty session — roster card, live terminal, click-to-open, kill button — instead of the old external-codex-delegate path's roaming battler with no session behind it. A new `poke-delegate.cjs` client CLI (installed alongside the existing hook shims, discovered the same way via `POKE_HOOK_SOCK`/`POKEHARNESS_AGENT_ID` inherited from the orchestrator's own harness pty — no separate auth token) posts `{cwd, label, effort, prompt}` over the same hooks Unix socket; main validates the parent session and cwd, spawns `codex exec --sandbox workspace-write -C <cwd> -c model_reasoning_effort=<effort, default medium> <prompt>` directly via `ptyManager`, and pushes the new session to the renderer to adopt (terminal + roster card, "↳ parent" link). Deliberately does NOT wire codex's own hooks for these sessions (traced `CODEX_HOOK_SHIM`'s "never stamp `harness_agent_id`" rule and kept it as-is — carving it out would misattribute a manually-run nested `codex` inside a claude orchestrator pty onto that orchestrator's own event channel); status/lifecycle instead come from the same generic pty-output parser and process-exit flow every other non-claude session already uses. Delegate sessions are excluded from disk persistence (no field exists to replay the prompt, and silently re-running a task on relaunch would be worse than losing it) — a delegate still live at quit time is simply not resurrected
- fixed the medium roster card's badge row painting past the card's right border (the "↺ changed from …" tick had no truncation): the card content now clips with `min-width:0` + `overflow:hidden`, the model badge and context % are pinned non-shrinking, and the tick alone flexes and truncates with an ellipsis — scoped to the roster-card medium variant, shared `ModelBadge` styling untouched. Implemented by a delegated codex gpt-5.6-luna run (verified and merged by the orchestrator) — the first delegation that spawned a live delegate battler in the garden end-to-end
- guarded against macOS dictation shifting the whole app sideways: composing voice input into xterm's hidden helper textarea makes Chromium scroll the document horizontally to reveal the IME caret, pushing the window content past the right edge. `overflow:hidden` now covers `html`/`body`/`#root` and a capture-phase scroll listener clamps those document-level containers back to 0 whenever anything moves them — panes that legitimately scroll (terminal scrollback, roster strip) are untouched. Implemented by a delegated codex gpt-5.6-luna run (verified and merged by the orchestrator)

## v1.7.0 — 2026-08-29

- done subagent pokemon stay in the garden until you dismiss them, instead of poofing away the instant they lose their completion battle: a losing battler now goes off-duty ('retired') — dimmed to 75% opacity, walks back toward its own roam corner, and keeps wandering the garden same as any other idling pokemon, never re-entering a battle. Its roster card (both the compact strip card and the full/sidebar card) flips to a green "done" status and a live/frozen elapsed readout ("done — ran Xm"), plus a small pokéball despawn button (icon-only in the compact strip, matching the compact "change pokemon" button's treatment) that plays a pokéball-recall animation in the garden — a red/white flash, the sprite shrinking into a pokéball that holds its own size, a few blinks, then gone — before the card actually disappears (instant, single-flash-frame under prefers-reduced-motion). Lifecycle correctness swept end to end: the 30-min roam age-out and every other completion path now land in 'retired' instead of poofing; a parent session's hard teardown still removes a retired (or mid-despawn) battler immediately, no orphans; a garden webgl-rebuild respawns a done battler as done, not as a fresh roamer; a resumed subagent whose battler is still sitting retired revives that exact battler in place instead of spawning a duplicate; and the parent-went-idle/blocked cleanup signal (`handleEndAll`) was fixed to skip retired/despawning battlers too, since it's a false-positive-prone signal that would otherwise have silently poofed away a done battler the user hadn't chosen to dismiss yet
- garden-split rework (Munder Difflin-inspired, user-approved hybrid of two mocked directions): in the 'garden' split view, the roster strip moved from spanning the full window width below both panes to living directly under the garden pane only, and the terminal is now a full-height right column (panel head, status strip, terminal, arceus dispatch box) reaching from under the topbar to the window bottom — free once the strip moved inside `.body-row`'s own left column (`.garden-column`), since `.body-row` then claims the whole body height and every row-flex sibling (`.drawer`/`.focus-sidebar`) stretches to match with no manual height math; hiding the terminal (the existing `»`/`«` tab) still lets the garden+strip column take the full width. Roster cards go compact by default (~half the old 220px width: sprite, truncated title, a colored status dot, a thin context sliver — no provider/species/tool line/model badge/percent/status pill); the SELECTED session's card alone expands to a trimmed "medium" card (sprite+name+dot, a muted "provider · species" line, then model badge + a smaller context bar + N% — deliberately NOT the tool line or the "working…" pill, since the terminal panel's own head already names the session and streams its activity). The strip's band height is a fixed 108px (sized off the medium card's own real row math, with headroom for a sprite whose rendered height isn't guaranteed to equal its box width) so switching selection never reflows the strip — compact cards just stretch to it, centered. Arceus keeps his ceremonial double-line frame at ~1.3× a compact card's width, brackets and star scaled down to match; subagent cards go compact too (task-label title + "↳ parent" line + a decorative sliver — no per-subagent telemetry exists to back a real one — with the elapsed-time line moved into the hover tooltip). Every card variant is the SAME component as before (`AgentRosterCard`/`SubagentRosterCard`) gated by a new `variant` prop, not a fork — FocusSidebar's vertical list and SessionsOverview's grid never pass it, so both render today's untouched full card. The strip's right edge now fades via a non-scrolling overlay (narrower strip, overflow is the common case now, not the exception). One inference flagged for review: the medium card also drops the evolution-hint row, which the approved spec didn't explicitly call out either way
- a session's terminal no longer goes dead when its CLI exits (ctrl+C out of claude, `/exit`, a crash): pty.ts now respawns the user's own shell under the same session id right after the existing "[process exited...]" notice, so the tab stays a live terminal (run `ls`, `git status`, or relaunch the agent by hand) instead of swallowing keystrokes forever — same as closing a foreground program in a real terminal drops you to its shell. The fallback shell inherits the exact env the CLI had, including the hook-routing stamps, so `claude --settings <path>` typed back in still reports to this session (a bare `claude` with no flags won't — Claude Code only wires hooks from an explicit `--settings` file, never from env alone). Guarded against a respawn loop (a fallback shell's own exit shows the plain dead state, no chaining) and against fighting deliberate teardown (closing a session, app quit, and a `--resume` respawn on relaunch all still work exactly as before — each already removes the session before its process actually dies). Arceus is excluded outright: his own resume/re-summon flow already treats a dead pty as its cue to act, and a shell riding along under his fixed id would just get killed moments later anyway. Also closed a real hazard the fallback shell would otherwise create: the exit path already clears a session's hook-authority tracking, which would have handed the very next byte of shell output straight to the regex tool-call parser — a stray "● Task(" or "(y/n)" in a `git log` or a file `cat` could have spawned a battle or flipped status to blocked. The exit signal now carries a `fallback` flag so the terminal drops its parser for good the instant the shell takes over, same as a plain-shell session never having one. New settings → terminal toggle, "drop to shell when a session exits" (default on)
- settings → usage gets a "main usage provider" picker (auto / claude code / codex cli, default auto = today's Claude-first-else-Codex behavior unchanged): the topbar chip's mini-gauges and the trainer-card popover now read off whichever provider you pick there, falling back to the auto pick whenever your chosen one has no data yet (still loading, or excluded via the usage-metrics checkboxes below it) so neither surface ever goes blank. Display-only — doesn't touch which providers actually get polled
- garden clicks now move you between views: in the garden/terminal split, clicking the garden (pokemon or ground) opens the fullscreen garden — a pokemon click also selects it; in fullscreen, clicking a pokemon selects it and returns to the split with the drawer open, while a ground click keeps the old deselect/free-look. Drag-pan, wheel-zoom, and Escape are unchanged. First change implemented by a delegated codex gpt-5.6-luna run (verified and merged by the orchestrator)
- external-codex-delegate battlers — the missing first hop is built: main/codexHooks.ts's `ensureCodexHooks` now idempotently merges a pokeharness `SessionStart`/`Stop` entry into codex's own `$CODEX_HOME/hooks.json` at boot (gated on a new `codexDelegateHooks` app setting, default on, and on codex actually being installed), preserving every other tool's own entries byte-faithfully — an existing entry is never overwritten, only appended after (or, if a stale pokeharness entry from an older install path is found, rewritten in place so it never duplicates). The invoked command is a new codex-flavored sibling shim (hookBridge.ts's `CODEX_HOOK_SHIM`), deliberately NOT a reuse of the claude shim: it never stamps `harness_agent_id`, because a delegate `codex exec` launched from inside a harness `claude` pty inherits that pty's whole environment — confirmed against codex's own source that a hook subprocess really does inherit the launching process's env unfiltered — so reusing the claude shim verbatim would leak the ORCHESTRATOR's own agentId onto every delegate event and misroute it onto the parent's own hook channel. Also resolved by reading codex's real source (openai/codex @ 0.150.1, not just docs): the previously-UNVERIFIED payload field names (`session_id`, `hook_event_name`) are confirmed identical to Claude's via codex's generated JSON schemas — no fix needed in hookBridge.ts/hookRouter.ts, both already assumed correctly. **Caveat that remains**: codex never auto-trusts a hooks.json change — it hashes each hook and only runs one once its `trusted_hash` is written into config.toml, which happens ONLY through the interactive TUI's startup "trust hooks" review screen; headless `codex exec` (how every delegate launches) has no such prompt. So the very first delegate run only fires once the user has separately opened one ordinary interactive codex session anywhere and picked "trust all and continue" — a one-time in-app toast (`app:getCodexHooksNotice`) tells them so the first time the merge actually changes the file. Full first-use sequence: restart the app (merges hooks.json, toast appears) → open any interactive `codex` session once and approve the hook prompt → delegate `codex exec` runs now fire it. Whether Orca (or any other tool already in hooks.json) is deleted is irrelevant either way — this merges alongside it, never replacing it.
- a pixel-art pokéball now sits left of the "pokéharness" wordmark in the topbar — 16px rect-grid icon in the real pokéball palette (the one deliberate exception to icons.tsx's currentColor convention), decorative for now, drag region and traffic-light spacing untouched
- battler ↔ task-id correlation (the long-term fix behind v1.6.0's 30-min age-out backstop and the "resumed agents are invisible" bug): a `Task` dispatch's `tool_use_id` — a documented Claude Code hook field, available at PreToolUse before any CLI-internal task-id exists — is now threaded onto the battler it spawns, then linked to that dispatch's real task-id the moment the parent's transcript shows the matching async-launch line (the same line the app already read for `toolUseResult.agentId` also carries the tool_use/tool_result pair's `tool_use_id`). Completions now retire the exact battler stamped with that task-id instead of guessing "the oldest roaming one"; the old heuristic remains only as a fallback for a battler whose correlation never landed. Piggybacking on the same wiring: a resumed subagent (its task-id dispatched async again after its first battler already fought and faded) now poofs back in with the same species/label and fights a real completion battle again, instead of staying invisible — the transcript watcher un-guards a task-id from its own completion-dedupe set the instant it sees that exact relaunch, closing the gap that used to swallow the resumed run's second notification (the resume-respawn's own species/label memory is in-process only, and rests on an unverified assumption that a resume relaunches through the same async-launch transcript shape a fresh dispatch does — see BACKLOG for both caveats). The 30-min age-out backstop (v1.6.0) and the async-dispatch counter it's built on are unchanged
- arceus cosmos backdrop de-zoomed: nebula source resolution doubled (320×200 → 640×400, half-size pixel chunks on screen), galaxy band narrowed (heat coverage 21% → 14.5%, haze halo 60% → 44%) so the frame reads as open sky instead of wall-to-wall nebula, starfield scaled to 1400 one-pixel stars (existing composition preserved, not reshuffled). CSS was already centered-cover (no distortion) and the calm zone stays behind arceus. The chunky warp burst is intentionally blocky sprite art and is unaffected by design
- sunset phase removed from the day/night cycle (user verdict after seeing it live: the orange wash muted the map). The cycle is now a single day↔night blend: morning ramps night out 5:20–8:30am, evening ramps night in 6:30–8:50pm, day stays completely untinted in between, and night is unchanged. All sunset code (wash, contact shadows, sun beam, glint, its vignette) deleted outright with a do-not-re-add note in the header. Side effect of the wider morning ramp: lamps still glow ~40% around 7am before fading out — early-morning lamplight, reads as intended
- diagnostics toggle-off no longer silences warns: pty nonzero exits, hookBridge drops, usageService failures, and counters divergence are diagnostic gold, so warn now logs unconditionally alongside error — only info chatter is still gated by the toggle. Settings panel copy updated to say so
- malformed hook payloads now log a short breadcrumb instead of up to 500 raw chars: the parse error, the payload length, and a 120-char prefix — cheap to read, without shipping paragraphs of user prompt/file text into a diagnostics bundle friends will export and share
- the `AGENT_ID` env var the hook shim reads is renamed to `POKEHARNESS_AGENT_ID` end-to-end (set in pty.ts, read by the generated shim), closing a suspected collision: a live hook capture showed a subagent's tool-call hooks carrying a different `AGENT_ID` value than the parent's, consistent with the Claude CLI setting its own env var of the same bare name for subagent-scoped hook commands. No compat shim needed — the shim script is force-regenerated on every app start, before any session can spawn, so setter and reader always agree. Not fully closed out: if that collision really was hitting a subagent's own PreToolUse/PostToolUse (not just SubagentStop, the only one with a live capture), this rename means those events stop landing on nobody's channel and start landing on the PARENT's — see BACKLOG's watch item, since hookRouter.ts doesn't yet special-case that path the way it does for SubagentStop
